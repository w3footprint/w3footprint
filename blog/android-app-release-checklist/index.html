Android app release checklist: 15 things to check before you upload

A practical pre-release checklist for Android apps: signing, versioning, target API, permissions, testing and store listing, in the order you should do them.

Android29 October 20262 min readBy the W3Footprint team

In this article

  1. Build and signing
  2. Quality
  3. Store and policy
  4. After you ship

Most release problems are not hard. They are forgotten. Use this checklist before every upload to Google Play. It is the one we run before our own releases.

Build and signing

  • Release build, not debug. Build an Android App Bundle (.aab) in release mode.
  • Upload key backed up. Store the keystore and passwords in at least two safe places. Use Play App Signing.
  • Version code increased. Every upload needs a higher versionCode than the last. Keep versionName readable for users.
  • Target and min SDK checked. Confirm the target API meets Google's current requirement.
  • Shrinking tested. If R8 or ProGuard is on, run the release build, not only debug. Missing keep rules cause crashes that only appear in production.

Quality

  • Fresh install test. Install the release build on a clean device, not an upgrade of your dev build.
  • Old and small phones. Test on a low-memory device and a small screen.
  • Bad network. Turn on airplane mode and a slow connection. The app should show a clear message, not freeze.
  • Permissions on a denied path. Deny each permission and check the app still behaves.
  • Crash reporting on. Make sure crash reports reach you before launch, so you see problems on day one.

Store and policy

  • Privacy policy URL live and matching the app.
  • Data safety form reviewed against every SDK in the app.
  • Screenshots and text that show real screens, in the languages you support.
  • Test account in the app access section if a login is required.
  • Staged rollout. Release to a small percentage first, watch crashes, then widen it.

After you ship

Watch the Android vitals tab for crashes and ANRs in the first days, and reply to early reviews. A quick fix released in a staged rollout beats a long wait.
